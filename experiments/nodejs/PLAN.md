# Node.js experiment plan

## Identity

Baseline: Go revision `f6863f145fd9d77c381b666654716d182bebc5cb`; working tree clean before this experiment. All changes stay in `experiments/nodejs`. Target: JavaScript ES modules, Node.js **24.22.3 LTS**, npm 11.19.1 bundled with that release, Linux ARM64 deployment; Linux ARM64 local verification. No compiler or transpiler. One event loop, no application workers. Native SQLite comes from Node itself. Plain JavaScript avoids compilation/build dependencies without changing production memory through a development runner.

Retain soft deletion even though user-facing prose says all related data is deleted: the baseline retains an credential-free tombstone with owner ID and the manual owner guard. All runtime dependencies are pinned by the Node release; no third-party runtime packages. npm lockfile records the empty dependency graph.

Container requires CA certificates, ICU (official Node full ICU), and bundled SQLite; repository certificates installed and passed through NODE_EXTRA_CA_CERTS. Production target linux/arm64. The initial official Debian slim runtime was replaced after user-requested image optimization by pinned Alpine 3.24 with the official musl Node 24.22.3 executable, libstdc++, libatomic and CA certificates. npm/Yarn remain only in verification stages. The Debian recipe is retained for reproducibility; prior resource trials remain attributed to Debian. No heap tuning; default V8 heap and libuv worker count.

## Layout, contracts, execution

`src/config.js`, `http.js`, `portal.js`, `storage.js`, `service.js`, `telegram.js`, `schedule.js`, `main.js`; `src/messages.json`; `migrations/001.sql`; `test/*.test.js`; package manifests, Dockerfile, compose.yaml, README.

Service uses positive numeric owners and opaque UUID enrollment IDs; status returns `{stage,checkedAt,fresh,inProgress,nextEligibleAt,error}` with epoch milliseconds. Stable error codes isolate collaborators from secrets. Synchronous storage admission/transactions plus owner flight records make admission atomic on the event loop. Async work uses AbortControllers; checks have waiter counts; removal installs its fence before awaiting drain. Storage exceptions trigger fatal diagnostics, ordinary not_found/exists do not. Portal owns cookies and shared agents; each logical check owns RPC state. Telegram receives ordered updates and detaches enrollment only. Scheduler calls service sequentially. All external requests are bounded; injected endpoint, HTTP exchange, clock, wait enable offline tests.

Configuration preserves `CASE_WATCH_TELEGRAM_BOT_TOKEN` and `CASE_WATCH_DB_PATH`; DB is independent from Go. Node timestamps/schema are not a Go compatibility promise. Commands (from experiment): `npm ci`, `npm run format:check`, `npm run check`, `npm test`, `npm run build`, `npm start`. No transpilation: build verifies syntax and creates a production tarball via npm pack. Run `CASE_WATCH_TELEGRAM_BOT_TOKEN=... CASE_WATCH_DB_PATH=/data/case-watch-node.db node src/main.js`. Docker from repo root: `docker build --platform linux/arm64 -f experiments/nodejs/Dockerfile -t case-watch-node:24.22.3 .`.

## Ordered milestones and acceptance

1. Scaffolding/config: pinned manifest/lock/toolchain, config tests rejecting invalid secrets safely.
2. Persistence: SQL versioning, WAL/FULL connection, atomic observations/removal; restart/rollback tests.
3. Portal: real five-step adapter, cookie sessions and bounds; sanitized fixtures through fake server, malformed/error/cancellation tests.
4. Workflows: cache/guards/shared work/removal/shutdown; deterministic clock/concurrency tests.
5. Telegram: exact messages/menu/intake, cancellation and polling; offline fake API tests.
6. Schedule/lifecycle: Warsaw slots and drain order; DST/missed/slow-slot tests and startup/shutdown checks.
7. Verification/package: formatter, syntax/static checks, all tests, release package; README records exact results and limitations; container instructions and later-comparison checklist. No benchmarks or shared harness.
