# Startup configuration

`case-watch run` reads environment variables (it does not load `.env` files). Startup validates syntax, key separation and permissions, the database schema, and every stored credential before starting Telegram polling or background work. It never provisions keys implicitly. See [operator commands and lifecycle](operations.md).

All three values are required: `CASE_WATCH_TELEGRAM_BOT_TOKEN`, `CASE_WATCH_DB_PATH`, and `CASE_WATCH_KEY_FILE`. Token syntax is a positive decimal bot identifier, a colon, and 35 ASCII letters, digits, underscores or hyphens. Local syntax validation does not verify Telegram acceptance. Paths must be nonblank and contain no NUL/newline. They are preserved as supplied; relative paths resolve against the process working directory. No defaults silently choose storage or key locations.

`CASE_WATCH_ALLOW_ALL_USERS` defaults to false only when absent. When present, it accepts exactly `true` or `false` after whitespace trimming. `CASE_WATCH_ALLOWED_USER_IDS` is a comma-separated list of positive decimal int64 IDs; whitespace is trimmed, duplicates collapse, and signs, overflow, empty entries and nondecimal characters fail. A wholly empty list is allowed only in allow-all mode. Malformed nonempty lists fail even in allow-all mode. Changes apply on restart.

See [the synthetic example](../.env.example). Diagnostics identify invalid variables without printing supplied values. Never print configuration structs, token values, credential input, or raw adapter errors. Provision the encryption key explicitly outside the repository and database directory, restrict the file to service-account mode 0600, and mount it separately read-only in containers. Startup never creates or replaces a missing key. The database directory must have no group/other permissions; existing database files must be regular mode-0600 files without symlinks or extra hard links. Backups are deferred under ADR 0008; losing storage or required keys can require re-enrollment.

`internal/auth.Policy` supplies the same `Allows` decision for handlers and background checks/delivery. `Authenticate` accepts only an ordinary private, non-bot sender with positive matching sender/chat IDs; adapters populate these from transport metadata. `Owner` binds operations to that sender and `RequireOwner` rejects other owners even in allow-all mode. Tracking and storage also enforce ownership independently of routing. Authorization withdrawal suppresses work without deleting retained state.
